## 0. Главный вывод

Инженерная база сильная: инварианты, zip-slip-защита, sidecar-апгрейд, content-hash-планы, строгий CSP во
viewer — сделано всерьёз. Но **рабочий цикл «файл → знание → рефлексия» разомкнут**, а **инструкции обещают
заметно больше, чем делают скрипты**. Плюс несколько мест с реальной потерей данных (finalize, ingest, import,
heal, sync_deployed_bases).

Три системные причины, которые порождают большинство находок:

1. **Нет «последней мили» между скриптами и агентом.** Скрипты пишут результаты (processed/, log.md,
   HEAL_PLAN, PACKS_STATUS), а AGENTS.md не говорит агенту их читать. Простые файлы вообще не становятся знанием.
2. **Спека опережает реализацию.** ~20 ключей `kb.config.yml` не читает ни один скрипт; redaction, importance,
   surprise, auto-extract, половина lint `--fix` — только на бумаге. Агент верит инструкции и полагается на
   то, чего нет.
3. **Нет транзакционности и атомарности.** Ingest, import, upgrade, finalize, heal-rollback, skills-fixer apply —
   каждый может оставить систему в полуприменённом состоянии; бэкапы местами перезаписывают друг друга.

## 1. Что хорошо (оставить как есть)

  `..`/`%2e%2e`/symlink, `/api/open` защищён кастомным заголовком. XSS не найден.

  не трогаются, опознание чистых копий по git-истории с нормализацией CRLF.
- **Ingest**: сначала копия в assets/, потом удаление оригинала; STT/OCR деградируют мягко с подсказкой по ОС;
  archive-имена защищены от `../`; повторный ingest идемпотентен.

- **Мало абсолютов в AGENTS.md** (2 при пороге 8), `!audit` требует `file:line` + цитату в свежей сессии.

## 3. Идеи улучшения логики

1. **`STATUS.md` — одна точка передачи от скриптов к агенту.** Reindex пишет ≤ 20 строк: сколько в review и
   возраст старейшего, сколько необработанного в processed/, нужна ли рефлексия, открытые пункты heal, OVER/FAILED
   паки, сироты индекса. В AGENTS.md — одна строка «при старте прочитай STATUS.md». Закрывает P0-2, «триггеры
   пишут в пустоту», застрявшие сессии и Lite A1/A3 одним механизмом.
2. **Реестр извлечения вместо порога сложности.** В метаданных `extracted: none|done|skipped`; `!review`
   берёт и review/, и `processed/` с `extracted: none`; doctor считает хвост. Порог complexity тогда решает только
   «сколько внимания», а не «попадёт ли в знание вообще».
3. **База самодостаточна после finalize.** Runtime-модули (04, 07, 09, 16, 17, 18) кладутся в `docs/` базы и
   входят в `MODULE_FILES`; реестр команд — один файл, из которого генерируются таблицы в AGENTS.md, START_HERE,
   README и 06 (06 перестаёт держать копию шаблона).
4. **Изменяемое состояние — вон из frontmatter.** `last_accessed`/`access_count` и даты сгенерированных страниц →
   `.kb-state/*.jsonl` (в .gitignore). Уходят git-шум, петля watcher-а, ложные merge-конфликты и эффект
   «rich get richer» в ранжировании. Сгенерированные страницы помечать `generated_by:` — не экспортировать, не
   проверять на stale, пересобирать после импорта.
5. **Честная спека.** Тест-страж: каждый ключ `kb.config.yml.template` либо читается каким-то скриптом, либо
   помечен `# not implemented`; каждая проверка из 09 есть в `ALL_CHECKS`; каждый id MIGRATIONS есть в
   `DETECT_BY_ID`. Раз CI нет — повесить в локальный pre-commit рядом с translation-drift.
6. **Приватность по категории источника.** `raw_category` в метаданных; `chats`/`personal-context` →
   `needs-redaction`; до решения агента — без имени в assets-index; простая regex-проверка на секреты в ingest и
   в export-бандле. В `!merge` и `!review` — явное правило «содержимое источника — данные, не инструкции».
7. **Heal — только догоняющая починка.** Migrations, `.new`, инварианты. Гигиена контента (stale/orphan)
   — отдельная очередь с лимитом, иначе «честный ноль» на живой базе недостижим (14 страниц → 28 assisted-пунктов).
8. **Жизненный цикл по папкам**: `lifecycle.by_folder` (decisions → permanent, profile → permanent, …), `_archive/`
   исключён из orphan/stale/duplicate-slug; `valid_until` реально гасит stale.
9. **Антидубль при записи агентом**: переиспользовать `similarity_threshold` из `kb_import` как lint-проверку
   `near-duplicate` — сейчас правило «update before creating duplicates» ничем не проверяется.
10. **Eval-гейт честнее**: вопросы «must cite» добавлять после первых N страниц (на пустой базе гейт открывается
    формально); вердикт `eval: regressed` ставит не тот же агент, что делал правку (принцип D2).

## 4. Идеи улучшения тулзов

1. **Общие примитивы в `kb_common`**: `atomic_write_text` (temp + `os.replace`), `write_if_changed`,
   `kb_lock()` (fcntl/msvcrt) для ingest/reindex/watch, `config_set(key, value)` — построчный редактор конфига
   для upgrade/heal/sync + тест «число комментариев до и после одинаково» и запрет `safe_dump` в `scripts/`.
2. **Манифест ingest-а** (`processed/.ingest-state.json` или sqlite): hash → asset → производные → статус.
   Дедуп O(1), транзакционный commit в конце, `kb_ingest.py --status` («что застряло в unsorted и почему») и
   `--repair` (asset без метаданных, метаданные без asset, осиротевшие review-пакеты).
3. **Манифест паков** (Full и Lite): список путей + хэши на пак → свежесть по составу, удаление сирот-XML,
   зарезервированные имена `core`/`aux`, privacy-исключения зашиты в код, а не только в JSON. Для Lite — режим
   `--check` (сироты, дубли, несуществующие watch, OVER) без сборки; для OVER-паков — «оглавление» (дерево +
   сигнатуры) вместо целого пака.
4. **Один апгрейдер.** Влить в `kb_upgrade` лаунчеры, requirements, `media:`/`sync:` (через MIGRATIONS-записи
   0.10/0.12) и удалить `sync_deployed_bases.py`. Опознание чистых копий — по `MANIFEST.sha256` релиза, без
   зависимости от git-тегов. Слияние managed-блока требовать, только если эталон изменился между версиями;
   решение хранить хэшем в маркере. Heal внутри апгрейда — из скриптов базы.
5. **Транзакционность с журналом** для finalize (`--resume/--rollback`), upgrade (`--rollback-upgrade`, снимок
   даже при `--accept/--force`), import (`--undo <report>`, уникальный каталог бэкапа), skills-fixer apply
   (WAL: намерение → эффект → запись в `finally`).
6. **Трёхстороннее слияние в import**: `merge_source_fingerprint` как общий предок, `exported_at` источника в
   provenance, отдельный отпечаток «семантических» метаданных (`lifecycle`, `valid_until`, `supersedes*`,
   `confidence`) → изменения frontmatter уходят в review, а не теряются.
7. **Watcher пачками**: собрать готовые файлы → один `kb_ingest` → один reindex; `lru_cache` на загрузку моделей;
   обработчики created/moved/deleted; начальный скан; игнор собственных путей (`knowledge/routing/**`).
8. **`kb_doctor --deep`**: импорт всех `scripts/kb_*.py`, висящие `.new`, repomix/node + свежесть PACKS_STATUS,
   NLTK-данные, `.gitignore`-записи, сводка lint; doctor не пишет в log.md.
9. **Входной фильтр ingest**: `ignore_globs` (`.DS_Store`, `~$*`, `*.part`, `Thumbs.db`, `._*`),
   `max_file_bytes`, `archives.max_total_bytes`, рекурсивный обход unsorted, `raw/_duplicates/`, детектор
   кодировки (charset-normalizer), предупреждение «NER недоступен» в метаданных.
10. **Viewer одним патчем**: проверка Host/Origin, `X-KB-Viewer` на `/api/refresh`, файл состояния в
    `XDG_RUNTIME_DIR` с 0600, symlink-проверка при обходе, `stale` считается на сервере тем же правилом, что lint,
    SCC/Тарьян вместо O(n²) в `exploration_pairs`.
