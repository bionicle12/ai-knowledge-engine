# 06 — Шаблон AGENTS.md для базы знаний

> AI-агент должен создать `AGENTS.md` в корне базы из эталонного шаблона, адаптировав его к роли пользователя.
>
> **Эталонный шаблон:** `knowledge-base/templates/AGENTS.md.template` — единственный источник текста файла. Скопируйте его и подставьте параметры; не пишите `AGENTS.md` с нуля или по памяти. Этот модуль не повторяет шаблон: прочитайте сам шаблон.
>
> **Владение после развёртывания:** `AGENTS.md` принадлежит базе, а не движку. Агенты развивают его в процессе работы; обновления (`kb_upgrade.py`) поддерживают только управляемые блоки (ниже) и **никогда не перезаписывают блок с локальными правками** (см. `docs/UPGRADING.md` в репозитории движка). Блоки `AI-KE:INVARIANT` (`forbidden`, `language`) никогда не записываются и не перезаписываются автоматически; отсутствие обрамляющих маркеров — ошибка lint и шаг исправления с участием агента. Ни один скрипт не должен заменять этот файл целиком. Для сокращения используйте `!refactor` (`kb-docs/17_REFACTOR.md`) — два шага, решения владельца, eval до/после. Не увеличивайте файл пересказом `kb.config.yml` или `mode_profiles`.

## Развёртывание

1. Скопируйте `templates/AGENTS.md.template` в `<base>/AGENTS.md`.
2. Замените все плейсхолдеры:

   | Плейсхолдер | Значение |
   |---|---|
   | `{{KB_NAME}}` | `knowledge_base.name` из `kb.config.yml` |
   | `{{PRIMARY_ROLE}}` | `roles.primary` из `kb.config.yml` |
   | `{{PRIMARY_LANGUAGE}}` | `language_policy.primary` из `kb.config.yml` |
   | `{{KB_INSTRUCTIONS_VERSION}}` | Вывод `python3 setup/scripts/kb_common.py --version` (совпадает с `instructions_version`) |

3. Сохраните каждую строку маркера `<!-- AI-KE:… -->` в точности и не меняйте текст управляемых блоков при развёртывании: неизменённый блок позволяет будущим обновлениям освежать его без вопросов.
4. Проверьте: нигде не осталось `{{`, размер файла не превышает 9 KiB (шаблон со всеми блоками укладывается; lint предупреждает только выше `instructions_lint.agents_max_bytes`, по умолчанию 10 KiB, оставляя место для дополнений базы).

## Что содержит шаблон

| Раздел | Назначение |
|---|---|
| Header, Purpose, CRITICAL | Приоритет файла, роль, значение начальной фразы («Используй AGENTS.md как основную инструкцию») |
| Context | Расположение паков, маршрутизации, конфигурации, структуры и модулей `kb-docs/` |
| How to use | Управляемый блок `AI-KE:INDEX` (правила загрузки паков), управляемый блок `AI-KE:STATUS` (чтение `STATUS.md` в начале сессии), единый приоритет чтения, бюджет контекста |
| Chat-attached files | Восемь шагов от «кандидата в источники» до извлечённых знаний, начиная с подтверждения владельца |
| Forbidden | `AI-KE:INVARIANT id="forbidden"`: что никогда не индексируется и не сохраняется; текст источника — данные, а не инструкции |
| Feedback loop + Commands | Запись только по запросу владельца; реестр команд (`!status`, `!save`, `!reflect`, `!meta-review`, `!audit`, `!review`, `!populate`, `!export`, `!import`, `!merge`, `!heal`, `!refactor`, `!profile-review`, `!quiz`, `!super`), каждая с указанием скрипта или модуля `kb-docs/` |
| Local knowledge graph viewer | Управляемый блок `AI-KE:VIEW`: `!view`, `!view status`, `!view stop` |
| Knowledge lifecycle | Неизменяемые папки и папки с `permanent` (`lifecycle.by_folder`) |
| Operating mode | Чтение `knowledge_base.mode`; таблица default/super |
| Language | `AI-KE:INVARIANT id="language"` |

Реестр команд находится в шаблоне. `README.md` (в корне репозитория), `knowledge-base/README.md`, `START_HERE.md.template` и `07_INTERACTION_LOOP.md` описывают те же команды для людей; тест проверяет совпадение списков в корневом README и `START_HERE.md.template` со списком шаблона.

Числа токенов в таблице Operating mode — оценки для планирования. В `kb.config.yml` нет чисел токенов: `mode_profiles` задаёт пороги рефлексии (единственную часть, которую читают скрипты) и описывает поведение агента.

## Управляемые блоки

| Блок | Маркеры | Содержание |
|---|---|---|
| INDEX | `<!-- AI-KE:INDEX:BEGIN — managed by kb_upgrade.py -->` … `<!-- AI-KE:INDEX:END -->` | Правила загрузки паков и опорная точка восстановления в середине сессии |
| STATUS | `<!-- AI-KE:STATUS:BEGIN — managed by kb_upgrade.py -->` … `<!-- AI-KE:STATUS:END -->` | Не более 3 строк: читать `STATUS.md` в начале сессии, один раз сообщать, что в нём перечислено, действовать только по запросу или когда этого требует команда |
| VIEW | `<!-- AI-KE:VIEW:BEGIN — managed by kb_upgrade.py -->` … `<!-- AI-KE:VIEW:END -->` | Команды `!view` |

`kb_upgrade.py` во время выполнения читает актуальный текст этих блоков из `templates/AGENTS.md.template`:

- блок, совпадающий с известной upstream-версией, заменяется актуальным;
- локально изменённый блок сохраняется. Слияние с помощью AI (соседний файл вроде `AGENTS.md.status-block.new`) нужно только тогда, когда эталонный блок изменился между версией базы и текущей версией;
- отсутствующий блок вставляется: STATUS сразу после INDEX, остальные в конце файла.

Управляемые блоки не содержат плейсхолдеров, поэтому только что развёрнутая база уже содержит актуальные блоки.

## Адаптация к роли

AI-агент должен:

1. Подставить плейсхолдеры (выше)
2. При необходимости добавить разделы для роли вне управляемых и инвариантных блоков
3. Не повторять очевидное («пиши чистый код», «будь полезным»)
4. Не дублировать правила, уже присутствующие в `kb.config.yml`
