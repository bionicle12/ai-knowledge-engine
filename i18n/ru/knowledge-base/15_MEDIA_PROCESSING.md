# 15 — Обработка медиа (расшифровка, OCR, архивы)

> Контракт преобразования **нетекстового ввода** — аудио, видео, изображений, архивов — в текст для маршрутизации, обогащения и индексации пайплайном.
>
> **Эталонные реализации:** `scripts/kb_stt.py` (речь в текст), `scripts/kb_ocr.py` (OCR) и помощник `_run_archive` в `scripts/kb_ingest.py`. Они подключены к `kb_ingest.py` и автоматически запускаются при приёме.

---

## Цели проектирования

1. **Из коробки на каждой платформе.** Без зависимости от системных инструментов, с которыми легко ошибиться. Компоненты по умолчанию устанавливаются через `pip` и включают свои кодеки и модели. В частности: **системный `ffmpeg` не требуется.**
2. **Локально и приватно.** Расшифровка и OCR выполняются на компьютере. Облачного бэкенда нет: `media.stt.allow_cloud` зарезервирован, пока ничто его не читает.
3. **Работа при отсутствии компонентов.** Если бэкенда нет, файл всё равно попадает в `assets/`, а пакет разбора содержит подсказку по установке для ОС: пайплайн никогда молча не теряет данные и не прерывает запуск из-за этого.
4. **Одна загрузка.** Модель Whisper и движок RapidOCR загружаются при первом использовании и остаются в памяти до конца процесса: один запуск приёма нескольких файлов оплачивает старт модели один раз.

## Установка

```bash
pip install -r requirements-media.txt   # faster-whisper + rapidocr
```

Для OCR текста не на китайском или английском (например кириллицы) также установите Tesseract с данными языка; см. [OCR](#ocr-images--scans--screenshots).

Проверка:

```bash
python3 scripts/kb_stt.py --check
python3 scripts/kb_ocr.py --check
python3 scripts/kb_doctor.py            # STT/OCR/ffmpeg appear in the report
```

## Настройки (`kb.config.yml` → `media`)

```yaml
media:
  stt:
    enabled: true
    backends: ["faster-whisper", "openai-whisper"]
    model: "small"          # tiny | base | small | medium | large-v3
    language: "auto"        # "auto" or ISO code ("ru", "en", …)
    device: "auto"          # auto | cpu | cuda
    compute_type: "int8"    # int8 (fast CPU) | float16 (GPU) | float32
    timestamps: true        # add [mm:ss] markers per segment
    allow_cloud: false      # reserved for a future cloud STT backend (not implemented)
  ocr:
    enabled: true
    backends: ["rapidocr", "tesseract"]
    language: "auto"        # "auto" = language_policy.primary + English, or "ru", "ru+en", [ru, en]
  archives:
    enabled: true
    max_files: 200          # members unpacked per archive
    max_total_mb: 500       # uncompressed total per archive (0 = no limit)
    max_member_mb: 200      # per member (0 = no limit)
```

## Речь в текст (STT)

- **Бэкенд по умолчанию: `faster-whisper`.** Аудио декодирует PyAV, включающий библиотеки FFmpeg, поэтому **системный `ffmpeg` не нужен** в macOS, Windows, Linux.
- **Резервный бэкенд: `openai-whisper`.** Используется, только если включён в `backends` и найден системный `ffmpeg`. `kb_common.find_ffmpeg()` ищет и вне `PATH` (например `/opt/homebrew/bin`), обходя проблему PATH графических приложений macOS.
- Результат: `processed/transcripts/<slug>.md`, заголовок с бэкендом, моделью, определённым языком и длительностью; сегменты с метками `[mm:ss]`, если включены.
- Метаданные: YAML extracted-metadata получает `stt_backend`, `stt_model`, `stt_language`, `stt_duration_seconds`, `stt_segments`.
- Если установленные бэкенды завершились с ошибкой, сообщение называет каждый и его ошибку, не утверждая отсутствие бэкенда, и указывает тип сбоя (см. [Сообщения об ошибках](#failure-messages)).

Поддерживаемый ввод: `.mp3 .wav .m4a .flac .ogg .oga .aac .wma .opus` (аудио) и `.mp4 .mov .webm .mkv .avi .m4v .mpg .mpeg` (видео: расшифровывается аудиодорожка).

## OCR (изображения / сканы / снимки экрана)

- **Бэкенд по умолчанию: `rapidocr-onnxruntime`** — включает свои ONNX-модели и среду выполнения, без системных зависимостей.
- **Резервный бэкенд: `tesseract`** через `pytesseract` (нужен системный исполняемый файл `tesseract`).
- **Язык.** `media.ocr.language` принимает ISO-коды (`"ru"`, `"ru+en"` или YAML-список `[ru, en]`; региональные метки вроде `ru-RU` считаются `ru`); `"auto"` означает `language_policy.primary` плюс английский. Tesseract получает собственные имена языков (`ru` → `rus`, `en` → `eng`, …; имя Tesseract вроде `chi_tra` передаётся без изменений), ограниченные установленными данными (`tesseract --list-langs`): язык без данных исключается; если не осталось ни одного, используется язык Tesseract по умолчанию (английский). Результат содержит предупреждение с отсутствующими данными и командой установки.
- Встроенная модель RapidOCR читает только китайский и английский и не принимает настройку языка. Если список содержит другие языки, сначала пробуется `tesseract`, если у него есть данные нужного языка; иначе сохраняется настроенный порядок. Результат RapidOCR для такого текста содержит предупреждение о возможных искажениях.
- Языковые данные Tesseract (английский входит в любую установку): `sudo apt install tesseract-ocr-rus` (Debian/Ubuntu, пакет на язык), `brew install tesseract-lang` (macOS) либо выбор языка в "Additional language data" установщика Windows. `python3 scripts/kb_ocr.py --check` выводит используемые языки, установленные и отсутствующие данные Tesseract; `python3 scripts/kb_doctor.py` показывает строки отсутствующих данных и установки как предупреждение `media:ocr`.
- Если установленные бэкенды завершились с ошибкой, сообщение перечисляет ошибку каждого вместо подсказки по установке (см. [Сообщения об ошибках](#failure-messages)).
- Результат: `processed/ocr/<slug>.md`.
- Поддерживаемый ввод: `.png .jpg .jpeg .webp .tif .tiff .bmp`.

## Архивы

- `.zip`, `.tar`, `.tar.gz`/`.tgz` распаковываются в собственную папку архива `raw/<category>/unsorted/` (имена элементов уплощаются и получают префикс имени архива); содержимое принимается в том же запуске. Краткий список записывается в `processed/markdown/` без NLP-обогащения.
- `.rar` стандартная библиотека **не** распаковывает: он направляется на разбор с подсказкой ручной распаковки или установки инструмента вроде `unar`.
- Ограничения защиты от архивных бомб для каждого архива: `media.archives.max_files`, `max_total_mb` (общий размер после распаковки), `max_member_mb`. Распаковывается один уровень: архив внутри архива не раскрывается, поэтому вложенность не умножает лимиты. Архив попадает в `review/needs-ai-decision/`, пакет объясняет ручное извлечение вложенного архива (после этого он распаковывается с собственными лимитами). Превышающие лимит, вложенные, уже принятые и нечитаемые элементы пропускаются и перечисляются под "Not unpacked".

## Сообщения об ошибках

Когда бэкенд установлен, но расшифровка/OCR не удаются, сообщение пакета начинается одним из вариантов:

| Начало сообщения | Значение |
|---|---|
| `no … backend could be imported` | Повреждённая установка; далее подсказка по установке. |
| `no … backend could start, so <file> was not read` | Проблема настройки, а не файла: модель не удалось скачать (первый запуск без сети, прокси, ограничение частоты Hugging Face) или загрузить (диск, память), среда ONNX не стартовала либо у Tesseract нет исполняемого файла или языковых данных. |
| `every installed … backend failed on <file>` | Хотя бы один бэкенд стартовал, но не прочитал файл, поэтому вероятная причина в файле: повреждение или недекодируемый бэкендом формат. |

## Поведение агента (важно)

Если поступает аудио/видео/изображение, а расшифровка/OCR недоступны, пакет `review/needs-ai-decision/` содержит точную команду установки для ОС пользователя. Агенту следует:

1. **Сначала выполнить `python3 scripts/kb_doctor.py`**, чтобы подтвердить доступные компоненты.
2. **Показать пользователю подсказку установки**, например «выполните `pip install -r requirements-media.txt`». **Не** вызывать `ffmpeg` вслепую и не предполагать наличие системных инструментов.
3. Только после установки бэкенда повторно обработать сохранённый файл: `python3 scripts/kb_ingest.py assets/<type>/<file>` (ресурс указан в пакете разбора). Обычный приём или переиндексация не повторяет попытку: файл уже ушёл из `raw/`. Не расшифровывать вручную в чате, если пользователь явно этого не предпочёл.

Если сообщение говорит, что бэкенд **не смог запуститься**, действуйте как при его отсутствии: покажите ошибку пользователю, запустите `python3 scripts/kb_doctor.py` и повторно обработайте ресурс после исправления настройки (первая загрузка модели один раз требует сети).

Если сообщение говорит, что все установленные бэкенды **завершились с ошибкой на файле**, причина, вероятно, в файле: сообщите о возможном повреждении или неподдерживаемом формате. Предлагайте проверку бэкенда (`kb_doctor.py`), только если другие файлы того же типа дают ту же ошибку.

## Поведение при завершении

Медиашаги никогда не выбрасывают исключение за пределы приёма: отсутствие бэкенда перехватывается и превращается в направление на разбор с подсказкой. Запуск только с медиафайлами без бэкендов всё равно завершается с `0` (файлы безопасно сохранены и поставлены в очередь), поэтому автоматизация и наблюдатели продолжают работу.
