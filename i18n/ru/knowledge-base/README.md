# Non-Code Knowledge Base — Модульные инструкции

> **Для кого:** AI-агент (Codex, Claude, GPT, Cursor), которому нужно развернуть и поддерживать локальную базу знаний специалиста.

## Что это

Набор инструкций для построения **Raw-First Knowledge Pipeline** — системы, в которой:

1. Пользователь складывает сырые материалы в `raw/`
2. Python-скрипт конвертирует их, запускает NLP-обогащение и записывает метаданные
3. Каждый конвертированный файл ждёт извлечения; сложные и чувствительные материалы попадают в очереди проверки
4. Чистые знания с данными о происхождении индексируются через Repomix
5. AI-агент учится на каждой рабочей сессии через цикл обратной связи
6. Lint следит за здоровьем базы, а autorun обновляет её по изменениям

## Порядок чтения

Агент должен читать модули **строго в этом порядке**. При развёртывании они находятся в `setup/`; развёрнутая база хранит их в `kb-docs/` (туда их копируют `02_INIT.md` и `finalize.sh`), куда ссылаются `AGENTS.md` и скрипты.

## Основные принципы

- **Raw-first:** сначала приём сырья, потом извлечение знаний
- **Markdown-first:** LLM читает `.md`, а не бинарные оригиналы
- **Local-first:** обработка идёт локально через Python + NLP
- **Clean index only:** Repomix индексирует только `knowledge/` и `assets-index/`
- **Provenance:** каждый факт привязан к источнику (хеш источника, ссылки на фрагменты)
- **Self-learning:** база улучшается через цикл обратной связи и запись результатов запросов
- **Cross-linked:** `[[wikilinks]]` связывают знания, таблицы маршрутизации масштабируют навигацию
- **Auto-maintained:** watcher + lint + autorun держат базу свежей
- **Privacy-by-default:** сырые данные и очереди проверки никогда не индексируются

## Быстрый старт для пользователя

```text
1. Откройте (или создайте) папку проекта, где должна находиться база
2. Скопируйте эту папку (knowledge-base/) в корень проекта, переименовав в setup/
3. Откройте проект в IDE с AI-агентом (Codex, Cursor, Claude Code и т. п.)
4. Скажите агенту: "Прочитай setup/README.md и setup/00_OVERVIEW.md, затем разверни
   базу знаний для [моей роли] внутри ./knowledge-base/. Когда kb_doctor завершится
   с кодом 0 (предупреждения допустимы), запусти setup/shell/finalize.sh,
   чтобы перенести базу в корень проекта."
5. Агент проверит окружение, задаст вопросы, создаст структуру и завершит
   развёртывание (база окажется плоско в корне проекта)
6. Начинайте работу: складывайте файлы в raw/
7. Запустите watcher: ./shell/watcher.sh
   (или вручную: ./shell/reindex.sh, либо launchers для двойного клика)
```

## Команды пользователя

То, что можно говорить AI-агенту в IDE:

| Команда | Что делает | Стоимость | Когда использовать |
|---------|------------|-----------|--------------------|
| `!status` | Читает `STATUS.md` (очереди проверки, ожидающее извлечение, срок рефлексии, пункты heal, проблемы индекса) и сообщает, что требует внимания | ~0.5K токенов | В начале сессии или когда непонятно, что делать дальше |
| `!view` | Запускает или повторно открывает локальный граф знаний только для чтения (`!view status` показывает URL, `!view stop` останавливает его) | 0 токенов | Чтобы без AI просматривать страницы, связи, метаданные, полнотекстовый поиск и панель здоровья (сироты, битые ссылки, устаревшие, неоднозначные) |
| `!save` | Сохраняет итог сессии с выводами и обработанными материалами | ~2K токенов | В конце продуктивной сессии или когда накопились полезные выводы |
| `!reflect` | Запускает рефлексию: синтез выводов более высокого уровня из накопленных фактов | ~15K токенов | Когда в базе появилось много нового материала или `STATUS.md` сообщает, что пора проводить рефлексию |
| `!meta-review` | Анализирует ещё не разобранные сохранённые итоги сессий: повторяющиеся паттерны → `interactions/meta-reviews/`, сессии получают `meta_reviewed: true` | ~5–15K токенов | Когда накопилось несколько сессий |
| `!audit` | L2 по пакам в новой сессии (`.repomix/audit/`) | ~5–20K / пак | Раз в 2–4 недели |
| `!profile-review` | Интервью `knowledge/profile/` (по 3 вопроса) | ~5–15K токенов | Когда lint предупреждает, или раз в месяц |
| `!quiz` | Пять вопросов о том, что уже лежит в базе; сначала самые дорогие ошибки | ~5–15K токенов | Когда хотите, чтобы база экзаменовала *вас* |
| `!review` | Разбирает очереди `review/` **и** конвертированные файлы в `processed/`, ещё ожидающие извлечения: извлекает устойчивые знания, обезличивает чувствительные материалы, задаёт точечные вопросы, когда нужен ввод | ~5–30K токенов | Когда `STATUS.md` показывает очередь проверки или извлечения |
| `!populate` | Перегенерирует `DATA_PLACEMENT_EXAMPLES.md` из YAML роли | ~50 токенов | После редактирования `examples/<role>.yml` |
| `!export` | Упаковывает базу для другой машины (`kb_export.py`) | ~100 токенов | Перед переносом знаний на другую машину |
| `!import` | Объединяет архивы из `sync/inbox/` (`kb_import.py`) и кратко пересказывает отчёт | ~200 токенов | После копирования архива с другой машины |
| `!merge` | Завершает импорт: разбирает `review/needs-merge/`, проверяет объединённые страницы на противоречия, связывает их, переиндексирует (`16_MERGE.md`) | ~5–30K токенов | После сообщения `!import` о конфликтах или новых страницах |
| `!heal` | Догоняющая починка после апгрейда (`kb_heal.py`, `18_HEAL.md`) | ~0–40K токенов | После `kb_upgrade.py` или предупреждения doctor |
| `!refactor` | Двухшаговое ужатие инструкций (`17_REFACTOR.md`) | ~5–40K токенов | Когда lint ругается на `agents-bytes` / протух `instructions_review`, или сменилась модель |
| `!super on/off` | Явно включает или выключает super mode | 0 токенов | См. ниже |
| `!super status` | Показывает текущий режим | 0 токенов | Быстрая проверка |

### Когда это уместно

- **`!status`** — первое действие в сессии; запускает `python3 scripts/kb_status.py`, который переписывает `STATUS.md` по текущему состоянию и выводит его
- **`!view`** — когда нужно посмотреть, что уже находится в `knowledge/`, или разобрать здоровье базы: чипы здоровья + очередь исправлений показывают каждую сироту, битую ссылку, устаревшую (по тому же правилу, что и `kb_lint`) или неоднозначную страницу со строкой-источником и кнопкой «открыть файл»; встроены полнотекстовый поиск, фокус на 1–3 хопа, кратчайший путь между двумя страницами и состояние UI в URL. `!view status` показывает URL, а `!view stop` останавливает локальный сервер
- **`!save`** — после любой продуктивной сессии от 45+ минут, где обсуждались документы, принимались решения или анализировались данные
- **`!reflect`** — после серии добавлений в базу (5+ новых страниц), перед важным стратегическим решением, или когда система сама говорит "пора"
- **`!audit`** — когда базу давно не проверяли (2+ недели) или перед большим блоком работы, чтобы убедиться в чистоте контекста
- **`!quiz`** — когда хотите, чтобы база экзаменовала вас по тому, что в ней уже есть (сначала самые дорогие ошибки)

### Когда это не имеет смысла

- **`!save`** — если сессия была тривиальной и без новых данных
- **`!reflect`** — если с прошлой рефлексии ничего не изменилось; система это проверит и пропустит
- **`!audit`** — если база совсем маленькая (<20 страниц) или только что создана

## Режимы работы

Система поддерживает два режима, переключаемых через `!super` (хранятся в `knowledge_base.mode`):

| Режим | Парадигма | Токены/день | Лучше для |
|------|-----------|------------:|-----------|
| `default` | Сначала Python, с ограничениями | ~3-4K | Ограниченный бюджет, повседневная работа |
| `super` | Сначала AI, по запросу | ~50-200K+ | Безлимитный план, интенсивное накопление знаний |

**default** оставляет рутинную работу Python (NLP-обогащение, сопоставление сущностей, lint), а для рефлексии и аудита обращается к агенту по расписанию.

**super** предписывает агенту свободно тратить токены: содержательные аннотации и семантическая проверка сущностей при записи страниц, важность с обоснованием, рефлексия после небольших изменений и предложение `!review` в начале сессии, когда в `review/needs-ai-decision/` есть элементы (запуск после согласия владельца). Скрипты меняют только триггер рефлексии; остальное — поведение агента из `mode_profiles.super` в `kb.config.yml`.

> ⚠️ **Super mode** может израсходовать дневной лимит токенов за одну активную сессию. Используйте только с безлимитными AI-планами.

### Что запускается автоматически и кто это делает

| Что | Кто | default | super |
|------|-----|---------|-------|
| NLP-обогащение (сущности, ключевые слова) | `kb_ingest.py`, каждый ingest | spaCy + RAKE (KeyBERT при установке), 0 токенов | то же |
| Сопоставление сущностей с существующими страницами | `kb_ingest.py` | Нечёткое сопоставление Python, 0 токенов | то же; агент перепроверяет при review |
| Оценка важности (1–10) | агент при записи страницы | только оценка | оценка + обоснование |
| Аннотации | агент при записи страницы | краткие | содержательные |
| Триггер рефлексии | `kb_reflect.py`, проверяется каждой переиндексацией; затем `STATUS.md` сообщает «reflection due» | сумма важности ≥ 25 либо любое изменение, когда с прошлой рефлексии (или развёртывания) прошло 7 дней | сумма важности ≥ 5, без минимального интервала; без изменений всё равно пропускается |
| Lint L1 (Python) | `kb_lint.py`, запускается reindex и watcher | 0 токенов | 0 токенов |
| Lint L2 (противоречия) | агент | по `!audit` | ежедневно, пока агент работает в сессии |
| Очередь проверки | агент | по `!review` | по `!review`, предлагается в начале сессии для `needs-ai-decision` |
| Фильтр неожиданности | — | пока не реализован (учитывается каждый ingest) | пока не реализован |
